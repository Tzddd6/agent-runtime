# v0.9：Agent 与工作流的模型累计预算

过去的 CPU、内存、pids 限制不能阻止动态 Agent 持续调用外部 API。模型响应统计也不能代替调用前的约束。本版在 ModelGateway 调用模型客户端前，增加工作流内共享的 ModelBudgetLedger。

## 行为与边界

每次准入同时扣减一次调用和该请求的 `max_tokens`。两级账本在同一个锁内检查并更新：Agent 默认 8 次 / 8192 输出 token，工作流默认 32 次 / 32768 输出 token。额度可设为 0；所有配置拒绝布尔数、负数、未知字段或超大值。

更换 Attempt、任务、Worker 或动态生成新 Agent 都不能重置工作流额度。同一 Agent 所有任务共享它的累计账本。只有整个工作流新建时才创建新的账本；因此这不是跨工作流或按日账户额度。网页允许降低本次运行的总上限，不能超过服务默认上限。

身份取自 Attempt capability，不能由请求正文指定。槽位等待结束后再次核查撤销与额度；排队时已撤销的请求不花额度，非法请求也不花额度。已经准入后出现本地错误、超时或取消，额度不返还，因为此时无法证明供应商没有执行或计费。429 表示预算拒绝或本地模型槽位超时，Worker 不自动重试。

成功响应的实际 token 统计与累计额度分开显示。额度使用“请求的最大输出 token”，不是实际 completion token；不限制输入 token，也不承诺人民币费用上限。供应商实际生成、计费及取消语义仍以其账单为准。HTTP/Gateway、动态任务和本机工具都是受信任代码，这不构成恶意代码沙箱。

## 代码关系

```text
AgentRegistry.register → 注册该 Agent 的模型额度
Runtime.run            → 创建工作流总账，绑定 ModelGateway
Worker 请求            → 校验 capability / 参数 → 等待模型槽
                       → 检查撤销 → 原子扣减 Agent + 工作流额度
                       → 调用本机模型代理 → 外部供应商
观察与落盘              → ACB.model_resources / summary.model_resources
                       → 网页 Agent 管理与历史索引
```

密钥仍只由独立模型服务持有；本版没有修改或重启该服务，升级网页不要求重新输入密钥。预算记录不含密钥、临时凭据、提示词或响应正文。Broker 保护密钥，Gateway 实施当前工作流策略；已有 Broker API 的管理员访问仍属于信任边界，不能视为系统级账单总开关。

## 配置

在 `--agents` 的 JSON 数组中可给 Agent 增加：

```json
[{"id":"writer","model_budget":{"calls":2,"output_tokens":1024}}]
```

工作流预算文件：

```json
{"calls":4,"output_tokens":2048}
```

通过 `python3 -m agent_runtime --model-budget examples/model_budget.json` 使用；Python API 为 `run(..., model_budget={...})`。网页“本次运行的模型额度”可编辑工作流上限；“Agent 管理”同时显示每个 Agent 和整个工作流的准入次数、累计输出额度、拒绝次数。旧历史没有该字段时明确显示无快照。

## 验收

`python3 -m unittest -q test_model_budget` 覆盖并发额度竞争、两级账本对账、非法配置、禁止重置、失败不返还、排队撤销、Agent 跨任务累计、动态身份无法绕过总额、网页上限与历史恢复。模型客户端均为离线模拟，不向供应商发送请求。

NUC 完整检查 157 项：149 通过、8 按环境跳过；另在真实委派 cgroup 内运行 10 项严格检查，全部通过，无残留 cgroup。其中两项是本版模型预算与独立 Agent 运行测试。证据存于 `validation/model-budget-2026-11-14/`。

生产网页另用 0 次 / 0 token 预算提交一项模型任务。预期结果是任务失败、Gateway 记录 429、两级准入次数均为 0、拒绝次数为 1。这里的失败是额度控制生效的验收结果，不是模型服务故障。网页测试不需要透露或重新配置现有 API 密钥。
