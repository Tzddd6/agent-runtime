## 二、赛题背景与说明

当前基于大语言模型（LLM）的智能体（Agent）系统正从“单Agent”快速演进到“多Agent协同”，广泛应用于自动编程、复杂任务规划、软件工程等场景。然而，现有多Agent系统大多停留在应用层框架（如 Workflow/Graph 调度），缺乏操作系统级的统一执行时（Runtime）支持，导致如下关键问题：

1. **缺乏统一调度：** 多Agent执行缺乏统一调度，易出现资源竞争与执行低效。
2. **上下文开销大：** 上下文（Context/KV Cache）频繁冗余拷贝，系统开销大。
3. **缺乏统一抽象：** 模型调用、工具调用与系统资源之间缺乏统一抽象。
4. **可观测性与控制不足：** 复杂任务执行过程中缺乏“系统级可观测性与控制能力”。

本赛题要求参赛者设计并实现一个面向多Agent系统的操作系统级执行时（Agent Runtime），将Agent提升为“操作系统一等公民”，实现对Agent任务的统一建模、调度与资源管理，并探索“AI Native OS”的关键机制。

## 三、赛题总体要求

本赛题要求参赛队伍从操作系统视角出发，围绕多智能体系统的执行与管理问题，设计并实现一个具备**统一调度、资源管理与上下文优化能力**的Agent运行时系统。参赛作品不仅需要具备完整功能，还应在关键机制上体现创新性，并通过实际应用场景验证系统有效性与性能优势。

## 四、具体技术要求

### 4.1 操作系统基础与兼容性

基于 **openEuler、openKylin、OpenHarmony** 等至少一个国内主流开源操作系统开发，鼓励在更多 Linux 发行版上编译、运行和测试。

### 4.2 多Agent任务调度

实现面向多Agent任务的调度机制，支持：

- 任务依赖；
- 动态生成任务；
- 资源感知调度策略。

### 4.3 统一的Agent执行抽象模型

设计统一的Agent执行抽象模型，明确：

- Agent生命周期管理；
- Agent状态转换；
- Agent与操作系统资源之间的关系。

### 4.4 Agent执行容错

设计Agent执行容错机制，通过隔离单体Agent故障，避免单点执行异常导致的多智能体系统性级联故障。

### 4.5 高效的上下文管理

设计并实现高效的上下文管理机制，包括：

- 上下文复用；
- 上下文压缩；
- 上下文隔离策略。

目标是降低多Agent执行开销。

### 4.6 复杂场景验证

构建复杂多Agent应用场景，验证系统在真实任务中的**可用性与稳定性**。

### 4.7 Agent间通信

实现Agent之间的高效通信机制。
