# AutoGen 对话驱动控制的受限复现

来源：Wu 等，AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation，arXiv:2308.08155v2，§2.2 Conversation Programming、Appendix C。

原文：https://arxiv.org/html/2308.08155v2#S2.SS2 。该节把回复计算与控制流分开，通过消息内容触发后续回复，并允许用程序规定终止条件和最大自动回复数。论文也支持更复杂的动态群聊；本项目没有实现完整 AutoGen 框架。

本项目独立实现 writer → critic → router 的两轮受限模式。writer 生成文本，critic 按明确的 JSON 协议返回 approved/revise 及意见。router 是确定性 Python 代码：通过则结束；请求修改则创建下一轮受信任模板任务；第二轮仍未通过则以 max_rounds 结束，accepted=false，不把“流程完成”误报为“答案通过”。协议错误导致 router 失败，不按默认通过处理。

动态创建任务依然要经过 Runtime 的整批 DAG 校验、资源准入、独立 Worker 和 cgroup 回收。模型无法指定 argv、工具、任务 ID 或轮数。最多四次模型调用，无自动模型重试。不同轮次的上下文只传上一轮答案和反馈，不无限累积全文。

浏览器场景为“限轮评审”，需要真实供应商密钥并消耗额度；自动测试使用本地模拟供应商，验证通过、修订、达到上限和非法协议。测试并未证明真实模型答案质量得到提升。该机制是对论文对话编程模式的范围有限的复现，不是项目原创算法。
