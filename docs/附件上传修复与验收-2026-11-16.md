# 附件上传修复与验收

2026-11-16，基于 v0.17 的独立修复分支。正在试验的 v0.18 执行优化没有混入此次上线。

## 原因与修复

1. 域名 nginx 的 `client_max_body_size` 原为 `24k`。图片及其他较大文件在抵达 Python 服务前即被 413 拦截。现为 `12m`，覆盖 8MiB 文件的 base64 和 JSON 开销；Python 仍限制实际文件 8MiB，其他端点继续保留原请求上限。登录、代理认证和 CSRF 检查保留，代理等待上限改为 45 秒。
2. 原后端仅支持 PNG/JPEG 和 UTF-8 文本，没有 PDF/Word 解析。现支持 PNG/JPEG/WebP/BMP、文字层 PDF、DOCX 和原有文本格式。
3. 网页增加拖拽文件、粘贴图片、逐文件验证进度、已就绪标记、提取字符数，以及 413/登录过期/超时的明确提示。批次中后续文件失败时保留已成功文件，不自动重发。上传期间禁用会话切换，避免把附件放进错误对话。输入区高度变化会为正文保留空间。

## 实现及安全边界

- `document_upload.py` 在独立 bubblewrap 子进程解析文档：不挂载用户 home、不传入服务环境或模型凭据、无网络、输入只读、临时目录独立。缺少隔离组件时拒绝降级运行。
- `document_parser.py` 使用 openEuler 仓库提供的 Poppler `pdftotext`；DOCX 用标准库 zip/XML 读取正文、表格文字及页眉页脚，不加载外部链接或执行宏。拒绝超限压缩包、异常路径、重复条目、宏和 XML 实体声明。
- 解析子进程设 512MiB 地址空间、10 秒 CPU、2MiB 输出文件、32 文件描述符限制，外层 14 秒截止并回收进程组。
- 原文件 8MiB；DOCX 最多 512 个 ZIP 条目、展开体积 32MiB、单正文 XML 4MiB。PDF 最多提取前 60 页；提取文字最多 120000 字符，截断明确提示。
- 原文件 UUID 私有存储，SQLite 附件及提取文字在同一事务写入，分别校验 SHA-256。附件绑定会话，跨会话访问被拒绝。图片校验实际格式、像素并去除元数据后规范化，最多 2 张；每条消息最多 4 个附件。
- 模型先收到最多 4000 字符预览、截取标记和工作区路径，需要全文时用受控 `file.read` 分页读取。文档内容视为不可信数据，不能改变工具权限。
- 旧版 `.doc`：该 openEuler 仓库未提供 antiword，当前给出“另存为 DOCX”提示；没有冒充已解析成功。扫描 PDF 没有文字层时要求先 OCR 或改为图片上传，当前未实现 PDF OCR。HEIC 请转为 JPEG。
- 文件内容可能随消息发送到当前模型供应商；不要上传密钥或不应外发的资料。文本密钥检测是附加保护，不保证发现所有敏感信息。

## 验收证据

- 完整常规回归：248 项，240 通过，8 项按环境跳过。上传、数据库与工程附件专项 21 项通过；最后的长文档范围提示调整后，9 项上传/数据库回归再次通过。
- 真实服务 API：上传一个大于旧 24KiB 上限的 PNG、一份 PDF 和一份 DOCX。一次真实模型请求正确识别图片验证码 `QUARTZ-729`、红色正方形与蓝色圆形、PDF 金额 95、Word 金额 73。执行成功，约 1.34 秒；单次功能验收不是性能对照结论。
- 浏览器：通过真实文件选择器一次选择上述三份文件，最终显示“已保存 3 个附件”，图片已就绪、PDF 31 字、DOCX 24 字。使用仅本机可见的 SSH 验收中转访问同一在线后端；该中转只允许固定测试附件，禁止模型和设置提交。
- 公网网关：未认证的 64KiB POST 返回 401，未再触发旧 413，登录仍被要求。这项检查与后端/浏览器验收分开记录，不声称绕过了 Basic 登录做公网已认证上传。
- 部署前确认无运行工作流，私有备份原 SQLite，仅重启网页服务；独立模型服务 PID 保持不变，没有读取、导出或落盘供应商 API 密钥。
