# v0.10：对话首页与独立运行控制台

用户入口为 `https://mc.tzddd.cn/agentrt/`，采用中央对话区、左侧会话历史和底部输入框。整机 CPU、内存、调度图、PID、Agent 控制等移到 `https://mc.tzddd.cn/agentrt/console`。两者共用原来的认证入口与 Runtime 服务，没有增加公网端口或更改 nginx、frp。

## 对话功能

支持直接对话、多 Agent 协作、写作与评审、免费本地文本统计、受控示例项目修复。建议按钮只填入问题，不自动提交付费请求。Enter 发送，Shift+Enter 换行，输入法组词时不会误触发送。回答支持安全的代码块展示和复制；模型文本不会作为 HTML 执行。

会话保存于 `/home/tzd/agent-runtime/web-runs/conversations/`。记录文件权限 0600，目录默认 0700，单文件上限 1 MiB，总量上限 100 个会话，每个会话 20 轮。到限后明确报错，不自动删除历史。当前沿用团队共享入口，拥有同一入口权限的人能够查看这些会话，并未实现独立用户账号隔离。对话不能用来保存 API 密钥。

追问的上下文由服务器读取已有记录构造，选取最近最多六轮成功对话、最多 24 KiB，额外加入当前提问。客户端不能提供 assistant 历史角色或覆盖既有回答。模型预算仍按每次运行累计，默认网页对话为 4 次调用和 4096 请求输出 token，可在输入框旁的“额度”中调整。输入 token 另计，不承诺人民币费用上限。

回答完成后一次返回，期间展示真实工作流步骤进度。没有伪造逐 token 流式输出。暂停与资源调度等细节仍在独立控制台；聊天中的“停止”会取消该轮底层工作流。新建对话不会暗中停止原有运行，也不会绕过全局单工作流限制。

## 请求与故障语义

每次发送附带会话 ID 和 request_id。服务器先持久化请求意图，再提交运行，再记录对应 job_id。同一 request_id 重复提交且参数一致时返回原 job_id，修改内容则拒绝。服务器没有确认 job_id 的请求保持不确定状态，不能自动重放；浏览器超时也不自动重试 POST。可通过“查看执行记录”在控制台核对。

若服务重启，未完成的会话轮次标为 interrupted，保留记录，不恢复执行或重放模型请求。会话恢复与 JobStore 的工作流观测恢复互相独立，已保存的回答不会因最近 20 个运行索引的内存窗口而丢失。异常或超大记录不会阻止服务启动。当前尚无会话归档 UI、多用户私有会话和跨工作流持久 Agent。

## 接口与文件

- `GET /api/chat/status`：模型就绪、CSRF、当前是否繁忙。不会采集并返回机器资源明细。
- `GET /api/chat/conversations`：会话目录。
- `GET /api/chat/conversations/<id>`：记录与运行进度。
- `POST /api/chat/turns`：有界、可去重的对话提交。
- `POST /api/jobs/<id>/cancel`：沿用既有取消入口。

页面为 `static/chat.html`、`chat.css`、`chat.js`。`chat_store.py` 负责持久记录、上下文选择和场景结果转换。`web.py` 串联对话和既有 Runtime。原 `index.html` 仍是完整控制台，支持 `/console` 与 `/console/`，查询参数 `?job=` 可定位某次对话的底层执行。
