# v0.19.1：真实正文增量与本地公式渲染

本版修复 `\[...\]`、`\(...\)` 在 Markdown 转义阶段丢失标记的问题，支持这两种形式及 `$$...$$`、`$...$`。公式先于强调/转义识别，代码块保持字面内容。使用本地打包的 KaTeX 0.19.1、CSS 与字体，不向第三方 CDN 发送对话。官方 npm 包 SHA512 完整性和逐文件 SHA256 写入静态目录 manifest，保留 MIT 许可证。

渲染设置 `trust:false`、`maxExpand:500`、`maxSize:10`、`throwOnError:false`。原始 HTML 仍按文字显示，未完成公式先保留正文，不能通过公式加载外部图片或执行任意 HTML。依据：[KaTeX 安全说明](https://katex.org/docs/security)、[定界符文档](https://katex.org/docs/autorender)。

## 流式链路

供应商 SSE → 受信任的一次模型调用子进程 → 单次本机回调能力 → Runtime 当前回答预览 → 已认证会话增量读取 → 网页。只转发 `delta.content`，不展示 `reasoning_content`。路由 JSON、内部 Agent 草稿、代码生成与电脑操作动作不作为用户回答流出；直接讲解、直接对话和最终汇总支持正文增量。暂未覆盖路由器直接返回 JSON 答案的情况，该路径仍等待完整协议校验。

每次回调使用独立的临时令牌，仅允许 `127.0.0.1` 的 `/progress`，完成/取消后撤销。Worker 不能使用自己的模型令牌伪造此回调。配置标记只对已安装兼容调用端的模型服务开启。浏览器约250ms读取活动轮次，状态/侧栏仍约1.5s更新；没有逐字播放已完成答案的假流式。

中间正文只在内存中预览，不进入可供后续模型信任的成功历史。生成期间明确提示尚未完成核验，停止或失败时使用最终状态替换预览。模型失败、流中断或计费状态未知时，不重放收费请求。使用量采用供应商最后事件的 usage；计费、续写和原有 Agent/工作流预算仍统一准入。协议依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。

新装的独立模型服务使用本版源码启动。网页使用本机模型代理时显式设置 `AGENTRT_PROVIDER_STREAMING=1`；未确认兼容调用端时保持关闭。当前 NUC 保持原持钥服务进程，只给其按次启动的可信子进程安装可选 SSE 代码，原代码有私有备份；供应商密钥没有导出、落盘或转移给工具/浏览器。

## 实测

一次真实讲解请求，输入137、输出2289、合计2426 token；一共1次调用。首个正文增量约1.010s，83字符时约1.339s，总耗时11.227s；收到79次真实正文增量，全部在完成前逐步到达。该结果是交互可用性验收，不是与直接调用的公平性能对照。

候选浏览器打开同一真实回答，89处公式、0处 KaTeX 解析错误；1280px视口无整页横向溢出。渲染正确不等于模型的所有数学断言正确。截图明确来自同版隔离候选，正式部署状态由交付收据单独记录。

初次预览选用的18890端口已有SSH服务，因此在状态读取阶段失败，没有发出模型请求，也没有改该SSH服务；随后使用确认空闲的本机18991完成验收。模拟流式、撤销、故障不重发、回调伪造与静态资源权限测试和最终回归见 validation/streaming-2026-11-16/。

40例真实任务对照仍沿用冻结5926336的原成绩：直调20/20，Runtime18/20，Runtime整体速度与token优势尚未证明。新增流式结果不替换该实验。
