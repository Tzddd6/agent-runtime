# v0.6 功能、架构审查与工作台升级

本轮审查覆盖任务校验、调度、Worker 启动/期限/清理、上下文和邮箱、模型网关及内存模型服务、工程测试与语义判定、网页控制面、采样和浏览器交互。保留单协调器拥有任务状态与预算账本的结构，扩展职责明确的索引和监控边界。没有引入额外服务框架或前端依赖，也没有新增真实模型调用。

## 发现与修复

| 问题 | 修改及验证 |
|---|---|
| FIFO 和资源适配实际使用手写准入分支，老化策略使用 AdmissionScheduler，监控决策口径不一致 | 三种策略均通过同一 choose() 路径选择任务；预算释放仍只能发生在 Executor 确认回收后。已有 FIFO 队首阻塞、资源适配及老化排空测试通过。 |
| 网页只读取直接服务节点的 CPU/内存上限，进程预算恒为128 | 合并祖先 cpu.max、cpuset.cpus.effective、memory.max、pids.max 的更紧上限；进程预算为控制面预留16个槽位。测试父节点0.75CPU/512MiB/96进程、子节点更宽松，准入结果为750m/384MiB/80进程。祖先上限仍不代表共享父节点的最低可用资源保证。 |
| 网页重启丢失最近运行索引 | 新增 JobStore：固定32位运行ID、512KiB索引文件上限、白名单字段、私有临时文件、fsync与原子替换。读取最近20次索引；坏文件和符号链接被拒绝。开始执行前先保存提交意图，磁盘失败不启动Worker；终态写入失败会展示存储告警。 |
| 重启可能让旧running记录看起来仍在执行 | 旧running/cancelling改标interrupted，不执行任何恢复调用；模型请求不会因恢复页面被重复提交。完成任务保留原始终态及历史采样，界面标明来自磁盘。 |
| 终态详情仍可能受到较旧监控水位限制 | 终态采用run返回的最终状态；仅运行中的详情按监控事件水位对齐，继续避免混用新事件和旧资源账本。 |
| 阶段记录被每秒刷新折叠 | 未变化的阶段保留DOM；变化时保留已展开阶段。实际浏览器确认刷新后分析记录仍展开。 |
| 切换记录或刚提交时可能短暂展示旧任务的成功结果 | 同步清空旧详情、曲线和导出状态；异步响应只有仍对应当前选中的运行才渲染。 |
| 工程拒绝错误仍写着纯整数/pricing模块 | 改为固定项目子集与实际模块名，不放宽AST白名单。 |
| HTTP初始请求头没有连接读取期限 | 网页连接在setup阶段即设6秒读取期限，保留原有认证、CSRF、Origin和请求体上限。 |

## 新版工作台

四个视图分别承载协作流程、资源监控、任务与拓扑、结果与事件。顶部固定展示选中运行的耗时、完成任务数、模型调用和token；停止按钮位于运行概览，不需要切去资源视图寻找。

运行历史支持按项目/ID搜索和状态筛选；任务表支持运行/等待/失败过滤，鼠标或键盘选中任务可读依赖、资源、实际统计、错误和输出。修复视图保留原版与修复后测试计数、阶段记录、最终评审及SHA256，展开源码后可对照原版和模型补丁。运行导出只导出该次详情，不包含控制台CSRF或供应商密钥配置。

保留整机、Runtime服务、工作流预留与Worker实际用量的不同口径；缺失值显示未知。布局增加桌面/窄屏断点、可见键盘焦点和tab键盘切换，并遵从减少动画偏好。浏览器实测包含桌面默认视口、历史搜索、任务诊断、阶段展开保留、标签切换和真实资源任务；未宣称覆盖所有浏览器和移动设备。

## 保留的边界

这是单机、单活跃工作流的受控执行时。JobStore恢复历史观察，不是事务执行恢复或副作用重放；邮箱仍是内存机制。cgroup强制资源限额不等于文件/网络安全沙箱，当前不接受任意模型命令或任意仓库执行。历史磁盘产物不自动删除，团队需归档管理容量；写入失败会阻止新提交或报告存储异常。此次没有重跑付费性能矩阵，也不把统一实现路径解读为性能优势。

`recovery_required`会保留隔离状态。管理员必须确认日志与残留进程/cgroup后，备份并将对应 `<job_id>/job.json` 改名归档，再重启网页；不能仅刷新页面或删除运行产物来解除隔离。不要重启模型服务来处理网页问题，否则其内存Key会清除。
