# 内存模型服务与升级交接

model_broker 是独立于网页进程的本机模型服务。它仅监听 127.0.0.1:18886，所有端点要求现有代理控制凭据 X-AgentRT-Proxy-Token。这个控制凭据不是供应商 API Key。供应商 Key 仅保存在模型服务内存，没有读取 Key 的 API；网页只查询 configured 布尔状态，并把用户的新配置转交模型服务。

网页配置 AGENTRT_MODEL_BROKER_URL=http://127.0.0.1:18886 和 AGENTRT_PROXY_TOKEN 后，ModelGateway 使用 BrokerClient；未配置此 URL 时，保留原有 DEEPSEEK_API_KEY 兼容路径。两种路径均不会把供应商 Key 交给 Agent Worker。网页进程可独立升级重启，模型服务自身重启或主机重启仍会清除其内存 Key。

模型服务统一限制两个调用槽、八个在途/排队请求、二十份完成响应历史。最多保存 4096 个请求身份摘要；达到上限时拒绝新请求，要求管理员轮换服务。结果淘汰不会允许同一 request_id 再次产生推理；同一身份携带不同正文会被拒绝。客户端不自动重试 POST，只重试只读轮询；丢失提交确认仍意味着远端可能已计算和计费。

每个调用有独立取消事件，由可信的一次性供应商代理子进程执行网络请求并受总期限监督。本地取消会通知模型服务回收代理，但不能证明供应商同时停止计算或计费。服务只保留必要的状态和响应，不把提示词、Key 或客户端异常原文写入请求账本、HTTP 日志或错误响应。

## 从旧进程交接

旧网页进程内的 Key 不通过调试器、proc 内存或返回 Key 的接口读取。管理员先启动新模型服务，再在 /home/tzd/.config/agentrt/ 下设置私有 broker-handoff.json：

```json
{"url":"http://127.0.0.1:18886","nonce":"a-unique-private-marker-at-least-16-chars"}
```

目录必须为运行用户所有且不向其他用户开放；标志与同目录 console.env 必须是运行用户所有的普通文件，权限不超过 0600。console.env 仍只含已有代理控制凭据，不含供应商 Key。URL 固定，不接受外部目的地址。

下一次明确授权的旧模型调用中，一次性模型代理本来就从 stdin 持有 Key；它在正常供应商请求前，经受保护的本机端点将 Key 交接至模型服务内存。确认交接后删除无 Key 的标志，再完成原来的那一次模型请求。若检查或交接失败，拒绝继续该次供应商请求，保留标志供管理员诊断。交接不是额外的供应商调用，但触发它的正常模型请求仍可能计费，必须记入实验预算。

先确认旧工作流已经结束、模型服务 configured=true，再切换网页进程使用模型服务。不能在交接前停掉唯一仍持有 Key 的旧进程。任意错误都不应通过打印 Key、写临时 Key 文件或放宽网络目的地址来排查。

## 边界

这仍是同一可信 OS 用户下的应用服务，不是恶意同 UID 代码的秘密隔离，也不是多租户凭据库。控制凭据必须保持私有，端口不通过 frp 或 Nginx 直接公开。历史响应可能包含用户任务内容，只有已授权的应用进程应访问。全局槽和内存边界改善升级与共享资源语义，不等于供应商端的费用硬封顶。
