# 调用期限与流式阶段诊断

旧45秒是RAM持钥父进程的绝对总期限，到时会终止受信模型子进程，并非模型固定45秒完成、JSON格式错误或已证明网络连接必然失败。旧失败未记录阶段，不能回溯断言卡在响应头前或流式中。

在原45秒基线新增两个同模型复杂格式复现均成功：约10.076秒和10.902秒，响应头约8.358秒和9.256秒到达；首正文约8.564秒和9.461秒，终态约9.894秒和10.802秒。公式、代码、表格、加粗通过，累计text等于最终正文。证据支持这两次主要耗时在接口开始响应前，不能把它细分成服务器排队、推理或网络中的某一种；也不能用两次成功抹掉旧超时。

新策略将同一个中转请求的期限按层对齐：供应商子进程90秒、broker客户端100秒、Worker到网关RPC110秒、基础LLM任务120秒。网页动态子任务使用同一可信策略；有续写时任务总期按受限次数放大。SDK默认仍尊重显式短任务期限，只有调用方传model_task_timeout时才应用策略。没有无限延长或不确定请求重放。提高等待额度本身不是提速，新的同条件对照两臂必须使用相同90秒供应商上限。

ModelError只允许固定错误代码跨子进程、broker、网关传递；绝对期限和socket超时保留MODEL_TIMEOUT，不返回原始异常/响应体。超时后远端计费仍可能未知，预算预留不撤销。

Linux已有pidfd时，空闲等待由20ms改为100ms；进程退出仍由pidfd立刻唤醒，fallback保持20ms，控制命令最迟约100ms检查，资源释放仍由回收检查决定。固定1秒回复的三次样本（顺序分组、非随机置信实验）CPU中位12.237ms→7.885ms，循环52→14，墙钟约1.049s→1.052s；不能声称模型变快或整体系统资源下降35%。HTTP opener在线程内复用，流式回调每次请求复用本地opener，不共享跨线程状态，不改变认证、禁代理和禁重定向。

临时阶段日志仅在owner私有0600配置且未过期时启用；只接受固定阶段名和数值，最多256KiB，不记录密钥、请求正文、最终回答或推理。测试结束删除启用标记，超时自动过期。模型来源固定https://ca.memofun.net/v1。
