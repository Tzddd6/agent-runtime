# 真实模型协作与受控 Python 修复实验

## 结果与范围

在 openEuler NUC 上使用现有控制台内存中的 DeepSeek 密钥完成真实调用，没有导出密钥或重启服务。修复后的六种在线配置全部完成：原版 25 个检查中 8 个失败，模型补丁均通过 9 个公开检查和 16 个独立检查，随后独立模型评审接受且回传正确源码 SHA256。

这是新建的、真实执行的三函数整数金额项目，有意植入折扣、免邮阈值、退款舍入缺陷；不是生产业务仓库，也不是任意 Python 仓库的通用修复能力。参考修复与独立测试向量未送入模型上下文。

## 完整流程

1. 公开需求、缺陷源码、少量公开例子交给现有四 Agent 控制台。
2. planner 制定计划；analyze 和 test_plan 按并发配置进行分析/测试设计；该次工作流的 review 任务按明确提示生成单字段 JSON 源码补丁，承担修复者角色。
3. 编排器对补丁做固定签名和 AST 白名单验证，不允许模型指定命令、路径或测试改动。
4. test_patch Worker 在独立 cgroup 中调用固定测试工具；工具使用独立目录、最小环境和 python -I -S，执行原版/补丁的真实 unittest。测试文件不接受模型修改。
5. 单独的模型评审读取需求、实际补丁、测试计数和哈希。最终成功同时要求代码通过检查、测试全部通过、评审 accepted=true 且哈希一致。

模型 Worker 由在线控制台管理，测试 Worker 由受限实验编排器管理，产物通过明确的父子运行 ID 关联。这是现有执行时上的组合场景，尚未包装成网页单个“修复任意仓库”按钮。

## 实际协作证据

四 Agent 标记传播检查通过。每个阶段生成新的 8 位标记，下游逐字回传实际收到的前驱标记；不事先向所有 Agent 提供期望标记。同时验证前驱成功到后继启动的事件顺序。这是可观察的输入使用行为证据，不证明模型内部因果。

限轮评审实际观察到 revision_requested → 第二轮 → max_rounds，协议与 gate 路由一致，accepted=false。该场景验证修订与强制终止，不能写成“模型最终评审批准”；独立工程修复场景的最终评审则全部批准。早期批准路径另有离线回归覆盖。

## 真实调用暴露的问题与费用

最初默认思考模式消耗了小输出预算，返回空正文但旧实现判为成功，导致补丁解析失败。保留了 13 份诊断记录、50 次供应商成功响应的用量；没有把这些失败从费用中排除。修复为显式 thinking.type=disabled，并拒绝空正文。该修复通过新代理子进程加载生效，没有重启或读取已保存的密钥。

为守住原定 100 次硬上限，修复后在线对照缩为每配置一次，另做协作和限轮评审，共 38 次响应。合计 **88 次真实模型响应**；调用预留上界为 90，未越过 100。输入合计 52,737 token，输出合计 22,263 token（已含思考 token，不能重复相加）。

按核验时官方 Flash 高峰单价：缓存未命中输入 2 元、命中输入 0.04 元、输出 8 元/百万 token，估算合计 **0.227632 元**；其中初批空正文诊断约 **0.154508 元**。实际账单未知，赠送余额、时段或后续价格变化均可能影响实际扣费。
