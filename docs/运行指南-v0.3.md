# v0.3 操作与验收

本版本是功能开发版。已覆盖赛题中依赖、动态任务、资源调度、执行隔离、上下文压缩复用和 Agent 通信的基本机制；最终参赛仍需要团队审查、扩展真实应用与完成系统性实验。

## 当前机器

通过 `ssh -p 2222 tzd@mc.tzddd.cn` 登录，在 `/home/tzd/agent-runtime` 工作。分支 `feature/runtime-v03-20261111`。不要使用旧 VM 的 dev 账号，不要修改 frp 或历史证据目录。

## 跑起来

```bash
cd /home/tzd/agent-runtime
python3 -m agent_runtime --tasks examples/dynamic.json
python3 -m agent_runtime --tasks examples/ipc.json
python3 tools/run_document.py README.md
python3 -m unittest -v
```

这些直接运行的 CLI 命令只做资源准入，事件标记 admission_only。真实 CPU/内存/pids 限制的可复现检查：

```bash
sudo systemd-run --unit=agentrt-validation --wait --pipe --collect \
  -p User=tzd -p Delegate=yes -p CPUQuota=200% -p MemoryMax=2G \
  -p TasksMax=256 -p RuntimeMaxSec=240 \
  /usr/bin/python3 "$PWD/tools/validate_linux.py"
```

验证报告和三轮基准原始样本保存在 reports/，执行明细在 runs/。这份脚本是本项目的验证脚本，并非赛事官方验收程序。

## 浏览器互动

打开 https://mc.tzddd.cn/agentrt/ ，使用现有网站账号密码登录。前三种场景不需要模型密钥；可查看运行状态、PID、资源、事件和结果，也可取消。单对话与四 Agent 模型协作需要在“模型配置”中输入个人供应商密钥，密钥只保留在服务进程内存，重启失效。四 Agent 场景会执行四次模型调用，输出仅为文本。

控制台已作为 agentrt-console.service 启动，在独立的委派 cgroup 子树管理 Worker，整个服务限额 2 核/2GiB。修改 Python 源码后需要管理员重启该项目服务；重启会终止正在执行的工作流，并丢失内存中的模型密钥和最近记录索引。磁盘执行产物仍保留。

管理员检查命令：`systemctl status agentrt-console`、`journalctl -u agentrt-console`。ECS 仅新增 /agentrt/ 路由与项目专用 SSH 转发，不修改其他网站或 frp 配置。私钥、代理共享头和网站认证文件不纳入源码包。

## 验证结果的解释

常规 unittest 共 30 项，其中四项只在 Linux 委派 cgroup 下启用；普通测试先通过 26 项，再由验证脚本单独通过 OOM、pids、脱离会话后代回收和超时重试四项。模型相关测试使用本地模拟供应商，尚无真实付费 API 验收。

上下文指标统计 JSON 对象的磁盘存储字节，不是 RSS、token 或 KV Cache 节省。benchmark 比较 sleep Worker 的特定队首阻塞模式，不能外推为通用性能提升。IPC 为回环 HTTP 引用传递，未实现共享内存、持久邮箱或崩溃恢复。所有 Worker 仍是相同 OS 身份，只运行可信配置；cgroup 是资源限制，不是完整恶意代码沙箱。

后续重点：以真实模型和真实工程任务收集实验；完善恢复与长期压力测试；依据团队亲自理解和修改的实现撰写参赛文档。
