# 工程闭环与常用能力 v0.17

2026-11-16。此版本重点减少工程任务的无效规划、反复搬运文件和付费总结，同时补齐真实验证与已测产物之间的关系。它仍是用户态单机 Runtime，不是工业级通用代码修复平台。

## 网页直接使用

在 https://mc.tzddd.cn/agentrt/ 新建对话，上传同一个小型项目的 `.py` 源码与 `test*.py` unittest 测试（2—4个文件），输入“修复这个Python工程，不要修改测试文件”。系统按原名导入文件，拒绝覆盖同名但不同的现有文件。也可在已有会话工程中继续请求修复。

实际链路：附件导入 → 文件/哈希快照 → 复现原测试 → 一个 Agent 生成 JSON 补丁 → 检查路径/哈希/语法 → 修改已有源码 → bubblewrap 内真实测试 → 下载完全相同的已测文件。模型不再承担独立的任务路由、重复分析和最终源码重写。第一次验证失败时，最多追加一次模型修正；传输失败或状态不明时不重放付费请求。

网页合成验收已上传 calc.py 和 test_calc.py，真实调用1次、3项测试通过，测试文件字节不变，生成的 calc.py 可按 SHA 下载。阶段耗时及源码下载已在浏览器核对。记录见 validation/engineering-2026-11-16/web-smoke.json。

## 控制与边界

- 控制状态机在 repair_loop.py，模型调用仍经过 ModelGateway、工作流/Agent累计账本和独立内存 broker。
- 准备、模型生成与校验分别作为 Runtime 任务运行，Worker、cgroup、取消和上下文授权路径继续有效。
- 工程快照最多32个Python文件、160KB。输入主要针对小型 unittest 项目；不支持任意项目安装依赖、pytest或大型仓库自动构建。上传暂存区不重复进入源码快照。
- workspace.apply_patch 最多修改6个已有源码文件，单文件40KB。先验证整批哈希与语法，再在工作目录锁内写入，写入失败会尝试回滚；不保证断电/崩溃时多文件原子性。禁止修改测试、暂存附件、已测产物与越界路径。
- 验证同时检查退出码、实际用例数和测试哈希。0测试、全部skip、测试被改均不算成功。测试代码自身仍需可信；共享服务用户不是恶意多租户隔离边界。
- 受控三个项目继续使用严格 AST 子集。公共失败会返回具体输入、预期与断言；隐藏用例只给数量。相同失败源码不会再次执行完全相同的验证。
- 只有明确无需工具、没有历史/附件的请求与简单问候走无包装单次回答；带历史、附件、知识资料的路径继续保留资料约束。一般复杂需求仍可按原通用路由处理。

## 29个工具和12份Skill

新增 workspace.inspect、workspace.import、workspace.apply_patch、workspace.test、library.search、library.read、tools.discover。前四个分别观察工程、导入本会话附件、修改受检源码和运行实际测试；资料工具只读本地整理笔记，能力发现按需返回参数和权限。Skill 不授予额外权限，也不自动安装外部可执行代码。

新增 engineering-repair、source-research、sql-review；补充 workspace-engineering、test-design、knowledge-analysis。资料包括 Python 测试与文件、SQLite、Git、HTTP、Linux cgroup，均带来源链接和版本。整理依据包括 [Python unittest](https://docs.python.org/3.11/library/unittest.html)、[sqlite3](https://docs.python.org/3.11/library/sqlite3.html)、[Git diff](https://git-scm.com/docs/git-diff)、[cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)。笔记不能替代对具体版本的核对。

可显式导入到自己的知识库：

```bash
python3 tools/import_library.py --data-dir /你的/web-runs
python3 tools/import_library.py --data-dir /你的/web-runs --apply
```

默认不写入；apply只新建缺失条目，不覆盖团队已修改版本。线上已导入6篇，原有资料保留，当前共7篇。

## 安全与验收
