# v0.20.0：真实上下文链路与用户隔离

新增组件已接入 `HTTP → Controller → Runtime → Worker → ModelGateway → provider`。验收固定 provider 返回值，检查框架发出的实际请求，不依赖模型是否听话，不使用供应商 API 密钥。

## 实际接入

- nginx 继续执行 Basic 认证，并用 `$remote_user` 覆盖 `X-AgentRT-User`。后端必须先校验独立代理 token，才接受此身份。请求 JSON、提示词和工具参数均不能更改用户身份。
- 每个登录用户有独立 Controller、会话、附件、知识库、工作区、CSRF 和 SQLite 记忆分区。旧团队目录仅由原 `remote` 登录账号继承。使用同一登录账号的成员仍属于同一用户；需要不同账号才能隔离。
- TenantRouter 启动时恢复持久化用户索引，发现损坏索引拒绝启动。所有用户共用全局准入锁和服务总资源限制，其他用户的活动工作流或待确认资源回收会阻止新准入。
- ModelGateway 根据 Runtime 签发的 Agent capability 检索记忆，每次调用重新校验已提交的记录。Agent 身份不取自模型提交的 `agent` 字段。
- 私有记忆仅由同用户的拥有 Agent 读取。`shared` 允许同用户其他 Agent，不能跨用户。使用 ContextStore 校验实际对象的权限与内容 SHA，缓存对象不等于授权。
- 每次模型调用的新增记忆最多 8192 UTF-8 字节，包括资料说明、格式与换行。这是可复现的字节预算，不是供应商 token 数。不会为了满足记忆预算截断用户原始问题。
- SQLite WAL、完整同步和事务保存已提交的记忆。数据库不可读或对象损坏会阻止模型调用，不自动重放请求；恢复存储后可提交新请求。已经发送给模型的内容无法撤回。
- 新增 `memory.remember`、`memory.recall`、`memory.forget`，全部通过 Worker IPC 的 Agent 凭证授权。网页“Agent 记忆”提供保存、私有/共享与移除；默认私有。不自动保存每一轮模型输出，不保存供应商密钥。
- 记忆上限每用户 1000 条、单条 32 KiB；删除后回收未引用对象。文本模式检查拒收常见私钥和 `sk-...` 内容，但不宣称可以识别所有格式的秘密。

## 实测分数与口径

| 套件 | 结果 | 覆盖范围 |
|---|---|---|
| 常规回归 | 327 项，318 通过、9 环境跳过 | 既有功能及新增组件 |
| 严格 cgroup v2 | 91/91，零残留 Attempt cgroup | CPU、OOM、PIDs、取消、后代、上下文等 |
| 真实上下文链路 | 15/15，零跳过 | 真实 HTTP、Worker、IPC、模型网关与持久化 |
| 真实网关访问矩阵 | 八组合均满足预期 | 同/不同用户、同/不同 Agent、private/shared；属于上述 15 项之一 |
| 故障注入检测 | 4/4 捕获 | 关闭用户分区、关闭 Agent 私有检查、关闭预算、存储故障后继续调用 |
| AIOS 原断言适配 | 26/26 | 保留前轮固定哈希原文件，不等于 AIOS 原生运行 |

真实链路测试进一步验证：跨用户会话/工作流/附件不可读，外来 CSRF 和伪造身份参数被拒；四 Agent 的实际请求只包含共享记忆；记录删除后不再注入；服务重启后用户分区恢复且不重放完成任务；杀死未提交写入进程不影响已提交记录；16 并发写入完整；数据库失效与对象损坏均先阻断、后经显式恢复重新使用。

测试使用固定模型返回，模型响应是测试夹具，不是自然语言质量评分。本轮供应商请求为 0；没有证据支持“全面超越直接调用”或任何公开榜单名次。

## 为什么没有官方排名

[AIOS 固定版本的访问矩阵文件](https://github.com/agiresearch/AIOS/blob/292d98f78c835499df18cdb6de6325bba1895862/tests/modules/memory/test_context_injector_access_matrix.py) 是 unittest 断言，没有该套件的提交/排名协议。本次没有向官方提交排行榜结果，排名为“未参榜”，不能把通过率 100% 说成第一名。上述 15 项是本项目实际链路验收，也不是外部 Agent 综合榜单。

## 复现与证据

在普通用户、Delegate=yes 的受限 systemd 临时服务中执行：

```bash
python3 -m unittest -v test_memory_access test_memory_runtime_chain
# 独立输出 reports/memory-chain-final，目录已存在时拒绝覆盖：
python3 tools/validate_memory_chain.py
```

严格执行时设置 `AGENTRT_TEST_CGROUP` 为临时服务启用 cpu/memory/pids 控制器的 Attempt 根。不要指向线上活跃 Attempt 根。常规测试中的固定 provider、临时目录与网络 loopback 都由测试自身创建，不需要配置真实 API。

汇总保存在 `validation/context-runtime-2026-11-17/`；原始合成测试日志保存在 NUC 候选树的 `reports/`，不把用户会话、私有数据库或 API 凭据提交到仓库。前轮 AIOS 适配结果保留为历史记录，新链路验收以本文件与本轮汇总为准。

生产发布要求保留认证、备份当前配置与数据库、确认没有活跃工作流、只重启网页服务。独立持钥模型服务不重启。若新入口验收失败，应恢复旧网页工作目录和 nginx 配置。
