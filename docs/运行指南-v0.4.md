# v0.4 资源管理器与论文机制

入口：https://mc.tzddd.cn/agentrt/ ，使用现有网页登录凭据。刷新页面后默认是“资源分配”场景，约 15 秒，无模型费用：启动后观察等待依赖、预留资源、真实 CPU/内存、PID 和释放。可调整 Worker 上限并比较 FIFO、资源适配和老化资源适配。

## 指标口径

- 顶部 HOST 是整台 NUC；SERVICE 是控制台所属 cgroup（含控制进程和 Worker），不是同一个统计范围。
- CPU 实际核心数 = 两次 cpu.stat usage_usec 差值 / 实际采样间隔；1.00 核等于一个逻辑 CPU 的完整时间。CPU 首次采样为空，事件间隔小于 100ms 时复用最近有效速率，不把未知补零，也不强行夹到配额。
- Worker 内存读取 Attempt cgroup 的 memory.current，包括工具后代、文件缓存和内核记账，不是主 PID RSS；终态显示 memory.peak，瞬时数值不再可测。
- 实线是实际用量，虚线是 Runtime 的预留账本。CPU/内存/pids/Worker 槽位的预留在回收成功后释放。进程数预留是可创建上限，不是实际进程数。
- 监控约每 0.4 秒采样，网页每秒轮询。每次运行保留最多 150 个聚合样本，内存索引保留最近 20 次。控制进程异常后的最后快照标为失效，不冒充当前资源状态。
- 遥测通过容量 8 的非阻塞队列发送，过载丢弃旧样本以保留最新状态，不阻塞任务执行。事件 sequence 与快照 event_sequence 水位用于防止把未来事件混入旧状态；遥测不是完整事务日志。
- 普通 CLI 未配置委派 cgroup 时只有准入账本，缺少 OS 用量显示“—”。生产控制台使用严格 cgroup。

## 论文机制及边界

| 来源 | 本版实现 | 边界 |
|---|---|---|
| AIOS §3.5 的 LRU-K | 有界 LRU-2 JSON 上下文缓存，保留磁盘压缩、哈希和逐次授权 | 无非驻留访问历史；不是 GPU KV Cache，也不等于论文全部内存管理 |
| AIOS 集中调度、Linux 公平目标 | resource_fit + 2 秒老化排空准入 aging_fit | 本项目组合改进，不是 AIOS RR/CFS/EEVDF 的复现；不抢占供应商推理 |
| AutoGen §2.2 对话编程 | writer/critic/router，根据结构化反馈动态生成修订轮次 | 最多两轮、四次模型调用；不执行模型给出的命令，不是完整 AutoGen |

详细出处、差异、测试分别见“论文机制-上下文.md”“论文机制-调度.md”“论文机制-多轮评审.md”。

“写作与评审修订”需要模型密钥。批准则提前结束；第二轮仍请求修改时以 max_rounds 结束并返回 accepted=false。流程成功不等于评审批准。密钥只在服务内存中，后端升级重启后需重新填写。

## 2026-11-11 NUC 实测

最终套件共 80 项，普通阶段会跳过六项需要真实委派 cgroup 的检查，验证脚本随后单独执行这六项（OOM、pids、后代回收、超时重试、真实采样、极低 CPU 配额下大载荷的启动截止）。无 Node 的目标机还会跳过一项前端离线逻辑检查；该项在开发机的 Node 上执行。本次 NUC 普通阶段通过 73 项、跳过 7 项，再单独通过六项真实 cgroup 验收；前端 Node 检查在开发机通过。开发机完整普通测试通过 74 项，跳过六项 Linux 检查。准确记录见 reports/linux-validation-latest.json 和完整日志。模型测试使用本地模拟供应商，不消耗个人 API 额度。

三轮受控小任务连续填充实验：大任务等待中位数 resource_fit 为 4.864 秒，aging_fit 为 2.426 秒；总耗时分别 5.089/5.048 秒，基本相同。老化改善这个负载中的大任务等待，不代表通用吞吐提升，也没有证明任意无限到达负载的等待上界。

最终代码三轮重放的逐次原始数据见 validation/2026-11-11-fairness-v04.json 和 2026-11-11-context-v04.json。

重复热上下文混合扫描实验：禁用缓存/LRU/LRU-2 的文件读取调用中位数为 224/146/130；用时中位数为 0.104/0.083/0.080 秒。OS 页缓存保留，读取调用不是物理磁盘 I/O；缓存预算统计原始 JSON 字节，Python 对象元数据和解码临时空间仍靠外层 cgroup 约束。

## 异常后的操作

recovery_required 表示控制面没有获得可靠的整体释放结论，新提交和密钥变更都会暂停。管理员应查看 agentrt-console 的服务日志、进程和尝试子组，停止该项目服务并确认其进程/子组已经回收后再启动；不要直接手动移除仍有成员的 cgroup，也不要触碰其他服务。重启后供应商密钥需要重新填写。普通单任务失败、超时或 OOM 在正常回收后不会触发这个系统级隔离。

模型调用的本地代理进程接受总期限和取消，避免滴流响应无限延长 socket 空闲超时；这不证明供应商同步停止计算或计费。启动文件 I/O、进程创建及 OS 调度不是硬实时可抢占操作，Worker 期限从启动入口计入，启动后若已过期立即终止，不能把它当硬实时系统。
