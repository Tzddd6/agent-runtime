# 调用过程与调度优化 v0.11

日期：2026-11-15。开发版；本次没有付费模型调用。

## 网页交互

每条回复前新增原生可折叠处理面板。运行中默认展开，完成后默认收起，用户的展开选择在轮询刷新间保留。显示工作流总耗时、实际步骤与 Attempt、运行/重试/完成/失败状态、模型或本地步骤类型。旧会话有执行记录时可补充显示，无须重新执行。

这里展示公开执行事件，不展示模型内部思考、提示词或模型密钥。模型调用次数来自准入账本，表示获准请求数；步骤时间包含执行和控制开销，不等于供应商纯推理时间。仍为完成后返回正文，没有实现逐 token 流式输出。

## 控制面改动

- CompletionWaiter 使用 Linux pidfd + selector 感知 Worker 退出，缩短原来固定轮询造成的空等；不支持时保留 20ms 轮询。pidfd 只负责通知，不能据此提前释放预算；仍须完成进程/后代清理后释放。
- 每次准入直接执行调度器选中的任务，减少重复扫描和输入顺序造成的额外循环，保留 FIFO、资源适配、老化与 DRF 的策略决策。
- 状态事件即时写入并同步 ACB，资源快照按调度/完成批次聚合。活动 Agent、活动集合变化都读取真实 cgroup；未变化的空闲 Agent 指标缓存最多 0.4 秒，并公开采样年龄。缓存仅用于遥测，资源预算和回收确认始终走原有路径。
- summary.json 增加 scheduling_stats 和 telemetry_stats，便于复查优化是否实际命中。

pidfd 依据：[Python os.pidfd_open](https://docs.python.org/3.11/library/os.html#os.pidfd_open)、[Linux pidfd_open 手册](https://man7.org/linux/man-pages/man2/pidfd_open.2.html)。通知机制不是抢占调度或崩溃续跑机制。

## 固定预算实测

基线为 264d2d7，基线目录保持不变。两版本同机、每配置五次，交错执行顺序；各版本预热一次并排除预热数据。总准入预算均为 2000 millicpu、1 GiB、128 pids、最多四个 Worker，启用真实 cgroups v2 及监控 observer。工作负载为 12 个依赖链任务、32 个独立任务、3 波每波 8 个任务，均为无模型的本地短任务。

| 工作负载 | 基线耗时中位数 | v0.11 中位数 | 降低 |
|---|---:|---:|---:|
| 依赖链 | 1.0269 s | 0.6865 s | 33.1% |
| 宽并行 | 1.2341 s | 1.1439 s | 7.3% |
| 分波依赖 | 0.9737 s | 0.8161 s | 16.2% |

宽并行协调进程 CPU 时间中位数从 0.47 s 降到 0.26 s。并非所有负载的调度决策次数都下降；依赖链更快响应退出可能触发更多决策。全部任务成功，且严格验收没有残留 Attempt cgroup。

这些结果说明本机控制开销下降，不能外推成真实模型协作的同比提速；网络、推理、长任务以及持续高负载仍需单独测量。五次重复不足以作广泛统计结论。

原始 30 次记录、测试和线上检查见 [validation/dispatch-2026-11-15](../validation/dispatch-2026-11-15/)。复现：

```bash
AGENTRT_TEST_CGROUP=/sys/fs/cgroup/实际委派路径/attempts python3 tools/benchmark_dispatch.py --baseline /path/to/264d2d7 --candidate "$PWD" --output reports/dispatch-benchmark.json
```

必须使用专用委派服务，不要把其他用户会话或系统服务 cgroup 当作测试目录。

## 验证与部署

常规测试发现 170 项：162 项通过，8 项因环境条件跳过。独立委派服务下另跑 12 项严格检查全部通过，覆盖 OOM、pids、超时、游离后代回收、Agent 聚合限制、模型预算和引用投递；无残留 cgroup。新增测试覆盖 pidfd 回退及关闭、反序依赖链、处理过程重试/终态，以及空闲遥测缓存的活动变更刷新。

部署只切换并重启网页服务，独立模型 broker 未重启，密钥未导出。网页通过已有对话验证折叠步骤和耗时，没有重新提交模型请求。线上仍使用原有 Basic 认证和服务端代理鉴权。
