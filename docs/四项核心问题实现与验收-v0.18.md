# 四项核心问题实现与验收（2026-11-16）

本报告对应官方功能挑战 proj3（https://os.educg.net/#/sList?TYPE=26OS_ZXHNF）中多 Agent 调度、上下文拷贝、执行抽象和可观测性四类困难。它是项目自查，不是官方验收结论。实现为 openEuler 上的用户态 Runtime。

## 1. 调度与资源竞争

- AgentControlBlock 管理身份、生命周期、并发、任务、上下文授权和累计模型额度。
- 工作流统一维护依赖图、动态任务、资源预留；可选择 FIFO、资源适配、老化适配、DRF。
- Agent 父 cgroup / Attempt 子 cgroup 管理 CPU、内存、swap 和 PIDs。Worker 加入限制后才获得执行许可。超时、终止和异常路径回收整个执行后代。
- 暂停表示停止新准入并等待在途任务收敛，不是模型生成中的抢占；终止撤销授权并回收任务。
- 新增无凭据的独立预加载进程：每次 Attempt 仍有独立 PID、会话及限额，不复用执行过 Agent 数据的进程。单个固定叶子任务默认 spawn，任务图使用预加载；控制进程退出时 fail closed。

## 2. Context 冗余与共享

- SHA 内容寻址、压缩、LRU-2 缓存、显式授权引用与按需分页回读。
- 多引用一次批量认证读取（最多128引用、合计4MiB）；Worker 结果仅返回 context_refs，不将收到的原文再次写入结果文件。
- 语义主张保留证据、来源、冲突和 Agent 转授权；不是将不同来源结论无条件合并。
- 预算视图保留当前目标及已提供历史窗口内的用户请求原文；旧助手内容可压缩。硬上限256KiB时拒绝请求，不悄悄裁掉用户目标。聊天历史本身仍有16轮/98304字节边界，不承诺无限历史。
- 这里优化应用层 JSON / 文本，不控制云端供应商 KV Cache；每个需要原文的 Worker 仍会物化数据，不是零拷贝。

## 3. 统一执行抽象

模型、工具、系统进程、Runtime 操作均有 execution_kind、Agent / Task / Attempt、输入引用、资源预留、PID / cgroup 和结构化结果。系统命令、文件、工程与网页工具仍受各自权限和沙箱约束。

两种进程后端都使用环境变量白名单，不继承控制进程中任意供应商密钥、SSH 凭据或代理凭据。密钥由独立模型服务保管，不进入 Worker、网页输出或评测附件。

SVG 产物必须绑定真实授权上游内容，校验完整 XML、尺寸界限、引用递归及危险外链；占位文字与截断代码不得作为成功 SVG。此校验不证明复杂插画的全部语义约束已经满足。

## 4. 系统观测与控制

独立运行控制台显示整机、服务、Worker 的不同统计口径，及 Agent、等待原因、Attempt 时间线、模型用量和控制结果。新增执行后端、进程启动累计、IPC 请求与正文体积。

服务指标计入预加载进程；Worker 峰值不冒充整个 Runtime 峰值。安全错误码解释上游502、截断与工具失败，不回显供应商异常正文。模型最后的“成功”不能覆盖已经失败的真实工具结果。

能力询问由 Runtime 工具注册信息回答。`web.fetch` 可读取公开 HTTPS 网页文本并记录来源；没有通用登录/复杂 JavaScript 浏览器或全网搜索插件。当前时间由 `clock.now` 读取，不浪费一次模型调用。

## 复现与运行

```bash
python3 -m unittest -q
python3 -m agent_runtime --tasks examples/dynamic.json --workers 2
python3 -m agent_runtime.web --host 127.0.0.1 --port 18881
# 严格资源检查需Linux cgroup v2与systemd Delegate；使用实际非root账号
sudo systemd-run --unit=agentrt-validation --wait --pipe --collect \
  -p User="$USER" -p Delegate=yes -p WorkingDirectory="$PWD" \
  /usr/bin/python3 "$PWD/tools/validate_scenario_resources.py"
```

严格检查会产生 `validation/core-2026-11-16/` 报告。真实模型实验会消费额度，应另建唯一输出目录并冻结协议；不自动重放已提交或状态不明的付费请求。普通测试不需要供应商密钥。
