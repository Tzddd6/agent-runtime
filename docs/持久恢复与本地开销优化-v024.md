# v0.24：持久检查点与本地关闭开销

本轮优先处理通俗版 PPT 中的故障恢复与固定开销。它没有改变既有四轮航空评测的冻结版本，也没有把旧成绩作为新版本成绩。

## 已接入的执行链

`runtime.run(..., checkpoint_dir=..., recovery_owner=...)` 在启动 Worker **之前**持久化执行意图，在确认结果后保存任务状态、动态任务、输出引用和上下文授权。写入使用私有权限、原子替换、文件与目录 fsync，并持有进程级文件锁。服务端供应商密钥、临时网关凭证不会写入检查点。

模型准入先持久化已经预留的调用次数及输出额度，再调用模型。恢复时不清零预算。检查点绑定原任务、配置、工作区、可信调用端身份和可用的模型配置标识，拒绝跨身份或变更配置的恢复。

检查点包含用户对话与任务结果，属于私有运行数据。不要提交到公开仓库或放进交付压缩包。默认网页数据目录 `web-runs/` 已排除提交。自定义检查点请放在仓库外。

## 恢复规则

1. 确认完成的步骤保留原输出，不重新执行。
2. 未开始的步骤继续遵守原依赖、资源及模型预算。
3. 中断的纯计算或只读白名单任务可以重建 Attempt。
4. 中断的模型调用、命令、写文件及未知工具效果不确定，阻止自动重放，需要核对外部实际结果。
5. 非正常退出后，旧委派 cgroup 必须已消失或确认无存活任务，才能恢复安全步骤。普通无 cgroup 运行遭到强杀时，拒绝自行认定资源已经回收。
6. 暂停状态和未持久化的邮箱消息需要显式核对，不擅自恢复。

这不是“任意操作恰好执行一次”的保证，也不是任意复杂任务的全自动断点续跑。被明确判为失败的任务不会因为恢复而自动重试。

## 使用入口

Python API 示例：

```python
run(tasks, output_dir="/private/run-output", checkpoint_dir="/private/checkpoint",
    recovery_owner="trusted-user-id", quiet=True)
# 原身份、任务和配置均保持一致，并确认旧执行资源已经回收：
run(tasks, output_dir="/private/run-output", checkpoint_dir="/private/checkpoint",
    recovery_owner="trusted-user-id", resume=True, quiet=True)
```

CLI 使用相同 `--tasks`、预算等配置，增加 `--checkpoint-dir /private/checkpoint`。恢复时额外加 `--resume`。`--recovery-owner` 必须由可信调用端确定，不能用模型声称的身份代替。

网页新工作流自动启用持久检查点。“结果与事件”显示检查点状态。已中断的动态、资源和文档安全演示可显式恢复。真实聊天、电脑操作、项目修复中的不确定模型/写操作不从此演示按钮重放。

## 性能改动

本地模型网关与上下文 IPC 的 HTTP 服务改用私有 socketpair 唤醒关闭，消除周期性轮询退出等待。它仍保留请求鉴权、在途处理线程收敛与 Worker/cgroup 回收，不通过降低资源隔离或忽略线程来提速。

8 条固定官方轨迹的初步剖析保持原请求、对话和奖励。首次基线运行在最后记录 Git 元数据时因新工作树所有权错误退出，已保留，不能伪称该次完整成功。正式速度结论需使用完成的交错顺序同条件回放，不从此剖析直接推广。

## 本轮验收范围

包括真实协调进程 SIGKILL、旧 cgroup 未回收时拒绝继续、回收后恢复、已完成写入不重复、预算不重置、动态子任务、跨身份拒绝、损坏上下文与符号链接拒绝，以及网页加载中断记录后的安全恢复。固定模型回复测量框架，不能作为新增模型能力或官方排名。
