# v0.5 网页项目修复

现有部署入口为 https://mc.tzddd.cn/agentrt/ ，使用原有网页登录。选择“Python 项目修复”，选择金额计算、时间区间或文本规范化，保留 Worker=2，点击“运行修复与验证”。运行时不能重复提交；可停止，但供应商可能已计费。

页面依次显示原始失败、问题分析、测试设计、生成补丁、真实测试、独立评审和最终结论。展开阶段记录可读实际模型响应；补丁源码单独折叠显示。修复前红灯是预期；只有修复后全部固定公开及独立用例通过、评审明确接受且其 SHA256 与实际测试源码一致，工作流才成功。Worker 退出码为零并不代表业务通过。

模型的测试建议用于后续修复上下文，建议中的测试代码不会直接执行。真实测试来自仓库固定检查器，模型无法更换测试。金额项目有 9+16 个用例，时间区间 9+13 个，文本规范化 8+13 个。三类小项目使用有意植入缺陷的模块，不能当成大规模任意工程修复基准。

每次修复最多四个模型请求，最大输出预算合计2048 token，输入另计。AST 拒绝或真实测试失败后不再请求最终评审。分析和测试建议可以并行，其余任务按实际依赖执行，所有产物通过 Runtime 的上下文引用传递。

网页总准入预算固定为2000 millicpu、1 GiB、128 pids，Worker 数只改变并发。服务可用上限更低时预算会相同地收紧。上线服务自身上限为2CPU、2GiB；独立模型代理上限0.5CPU、512MiB，二者在串并行配置中保持不变。云端模型计算不属于 NUC cgroup 预算。CLI run() 未显式传 budget 时仍保留原来的按 workers 计算默认值；正式实验通过网页并严格核验实际预算。

部署代码目录为 `/home/tzd/agent-runtime-repair-20261111`；网页产物继续写 `/home/tzd/agent-runtime/web-runs/<console_job>/<workflow>/`。网页内存只索引最近20次，服务重启会清空索引，磁盘产物仍在。模型服务与网页是两个 systemd 单元：`agentrt-model-broker` 与 `agentrt-console`；只重启网页不会清空供应商 Key。不要为网页升级顺手重启模型服务。

固定预算重复实验命令（在仓库根目录；代理控制凭据通过既有私有服务环境注入，不要放命令行）：

```bash
python3 tools/benchmark_projects.py --output-dir reports/project-benchmark-new --plan-only
python3 tools/benchmark_projects.py --output-dir reports/project-benchmark-new --execute
```

--execute 会发起最多216次付费模型请求，3项目×2并发×3策略×3重复，总计54个工作流。已有输出目录会使用持久检查点，已知任务只轮询；提交确认丢失时停止，不能自动重发。每次运行立即归档 detail.json、metrics.json，避免被网页20次历史淘汰。

前端没有任意仓库上传或任意 shell 输入。AST 白名单只允许固定签名及有限运算，字符串项目开放少数纯字符串方法；仍需 Linux cgroup 和执行超时限制资源。当前机制不承诺对恶意任意 Python 的完整安全隔离。
