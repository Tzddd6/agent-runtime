# 上下文调控与语义共享 v0.16

日期：2026-11-16。本文对应本轮源码和 `validation/context-2026-11-16/`，按赛题 4.5、4.7 补强上下文与通信，同时改善 4.3、4.4 的结果管理和故障隔离。

## 数据通路

Runtime 保留 Workflow → AgentControlBlock → Task → Attempt → Worker PID → cgroup 映射。任务发布不可变 JSON 对象后，context.py 按 SHA-256 去重、可选 gzip 存储和 LRU-2 缓存。文件权限为私有目录 0700、文件 0600，读取校验哈希并拒绝符号链接。

模型 Worker 一次 context_view RPC 获取本次授权视图，替代逐对象多次取回。非模型任务继续使用原始完整输入。context_control.py 负责字节预算、片段选择、来源与冲突提示，原始对象始终保留。选取不调用摘要模型或嵌入服务，因此没有额外付费请求。

balanced 默认软预算 18,000 字节，硬上限 98,304 字节。full 对照模式最多 512 KiB。超额视图保留当前 user_request 和显式 constraints/requirements，再按中英文关键词相关性与重要标记选择片段，并在多来源之间轮流分配。视图标注 partial 和 source_ref。被固定的目标本身超过硬上限时明确失败，不静默裁掉。图片走独立通道，不混入文本索引。

这不是无损语义压缩，不保证从历史对话中识别并固定所有隐含约束。字节是序列化视图正文的计数，不能等同于真实 tokenizer 计数、完整请求或费用。真正输入 token 以供应商 usage 另行记录。

## 检索、分页与权限

新增两项受控工具，工具总数从 20 变为 22，Skill 保持 9 份：

| 工具 | 参数 | 行为 |
|---|---|---|
| context.search | query、limit（1—8） | 检索当前 Agent 授权对象，返回片段、SHA 引用、来源与已观察到的冲突 |
| context.read | source_ref、offset、limit | 原文按字符分页，单页最多 8,000 字符，返回后续偏移 |

检索是中文分词/英文词项与结构化字段匹配，没有向量数据库、神经语义相似度或全库穷举保证。每对象最多索引 2,048 个单元、每次检索最多检查 256 个授权引用，索引缓存限 2 MiB。缓存命中前仍校验原对象权限与完整性。

依赖结果只授权给消费者。动态子任务仅能通过受检 `_shared_refs` 转授父 Agent 已持有的引用。Runtime 在发放前验证整批引用，内容哈希不能单独充当访问凭据。Attempt 临时 token 到期撤销，局部摘要或索引缓存不能绕过读取检查。

这些是同一工作流的 API 访问控制，不构成不同恶意 OS 用户之间的安全隔离。受控命令另用 bubblewrap 和 cgroup；普通 Worker 仍由同一服务用户运行。

## 语义主张与结果契约

Agent 可以发布如下结构：

```json
{"semantic_facts":[{"subject":"run_config","predicate":"workers","value":2}]}
```

Runtime 为结果标注 task/agent/action/attempt 来源。模型内容标为 model_claim，工具结果标为 tool_observation。相同 subject/predicate 的不同值会一并返回，消费者需继续验证。主张不会自动变成已验证事实；工具读取的外部文本也不能获得系统指令权限。

任务可以显式声明 `result_contract: "json_object"` 或 `"semantic_facts"`。后者要求 1—16 条有界三元组，空列表在共享结果发布前失败。无关健康分支继续执行，依赖失败分支按现有规则跳过。此检查不重试付费调用。契约目前由 SDK/任务配置声明，不能宣称所有自动路由模型输出都已经受同一契约保证。

`examples/context-sharing.json` 免费演示邮箱、ACK、授权引用和两个冲突主张。Linux 实际 Worker 测试覆盖合法转授、伪造转授失败、无关分支继续、长上下文视图与空主张发布失败。

## 实测

openEuler 上常规发现 230 项，222 通过，8 项因特定环境开关跳过；另外在独立委派服务运行 16 项严格 cgroup 检查全部通过，没有残留 Attempt 组。

上下文对照采用相同长上游合成数据、两个确定性生产者和一个真实模型消费者。两种模式各 3 次，交错执行，总准入预算均为 2 核/1 GiB。要求模型保留两个随机编号与 must_preserve_tests 约束，6 次均通过。

| 指标 | full | balanced |
|---|---:|---:|
| 实际输入 token 合计 | 62,512 | 8,869 |
| 实际输出 token 合计 | 126 | 118 |
| 工作流耗时中位数 | 1.659 秒 | 1.080 秒 |
| 本机 Worker CPU 中位数 | 0.218 秒 | 0.199 秒 |

本负载输入减少 85.8%，耗时中位数约减少 34.9%。CPU 不含独立 broker 和供应商云端计算，没有由此证明 RAM 峰值稳定下降。这是长上下文专项，不是重新完成 v0.15 全套直接 API 对照。

真实模型协作最初三次调用中，一个生产者返回空 semantic_facts，导致检索未找到冲突，最终语义验收失败。原始失败保留于 real-models.json。随后增加结果契约，用独立样本执行两名生产 Agent 和一名裁判 Agent 的三次真实调用：消费者获得两条 model_claim，保留 workers=2/3 冲突，裁判要求继续核验，通过语义验收。详见 semantic-contract.json。不得把这两个实验合并成“全部模型调用成功”。

网页 balanced 模式已通过真实一次路由调用，答案命中合成标记，context_control_summary 记录视图数据。首次无效会话 ID 被入口拒绝；另一次过小输出总预算在供应商调用前拒绝（模型调用数为 0）。修正测试参数后验收成功，没有自动重放付费请求。

## 论文关系与边界

[AIOS 原文](https://arxiv.org/html/2403.16971v5)提供 Runtime 分层与 Agent 执行管理的参考；[MemGPT 原文](https://arxiv.org/html/2310.08560v2)启发内外上下文分层和按需取回。本实现没有复现其全部机制，不接管模型内部 KV Cache，也不实现供应商推理抢占。

仍需推进：真实工程闭环成功率、较少路由轮数、长期历史约束识别、严格租户隔离、崩溃后安全恢复。v0.15 直接 API 对照中的负面结果仍保留，v0.16 尚未全面重测。
