# 固定模型返回的框架对照（2026-11-17）

100 段原始对话（Runtime 与 direct 各 50），每组重复两遍，baseline/candidate/direct 共 600 次任务执行。所有模型请求摘要、完整对话与官方 ALL 判分均与录制轨迹一致；本实验没有供应商请求，不是新模型能力评分。

| 指标 | 旧 Runtime | 优化 Runtime | direct |
|---|---:|---:|---:|
| 200 次任务总秒数 | 358.260 | 268.979 | 156.033 |
| cgroup CPU 秒 | 300.742 | 230.442 | 165.842 |
| 最大 cgroup 内存 MiB | 455.73 | 329.27 | 289.04 |

相对旧 Runtime，耗时下降 24.92%，CPU 时间下降 23.38%；优化后仍为 direct 耗时的 1.72 倍。内存记账受共享页和页缓存归属影响，不能直接推断固有内存节省。优化提交为 `4cf27b8`；后续多 API 功能不在这些计时样本内。外部重启打断的部分样本已排除，最后一组三臂全部在重启后重新运行，组内不跨启动周期。

原始真实模型分数保持 Runtime 39/50、direct 41/50。Runtime 的 11 个失败均有数据库状态不匹配，未发现传输故障；不能靠通用重试解决，且重放不确定的模型调用可能增加费用和重复副作用。已定位漏操作、支付方式、行李费用、取消规则和乘客信息等语义错误。两组 6 个不一致样本的精确 McNemar p=0.6875，不能据此宣称能力优势。

框架优化包括无凭据预加载器跨串行工作流复用、每 Attempt 保留独立 Worker/cgroup、跳过空上下文 IPC，以及显式绑定模型配置。17 项聚焦测试包含真实 OOM、超时、预加载器调用中死亡、下一工作流恢复及禁止重复提交；全量回归另行记录。
