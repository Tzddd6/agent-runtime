# 02. 聚焦版 Playwright 验收、同条件交错对照与赛制合规补齐

## 一、聚焦版 Playwright 浏览器端到端验收

### 1.1 原则
- 使用 **Playwright** 驱动真实浏览器操作 `http://127.0.0.1:8765/console/`，**严禁绕过页面按钮直接调后端 API**。
- 先使用**固定桩模型返回**跑通全部确定性链路（零费用、快速稳定），再接入**少量真实 DeepSeek 模型**做端到端冒烟验证。
- **通过标准**：不是“页面没报错”，而是 **结果正确 + 前后端状态一致 + 失败有明确原因 + 无重复执行 + 资源与临时目录已回收**。

### 1.2 核心必测清单（聚焦高价值系统链路）
1. **多文件修复完整链路**：选 `order_service` → 提交 → 实时观测 DAG/Agent/PID/`cgroup`/Token/`ctx_ref` 更新 → 完成后点击下载产物 → 校验压缩包内源码 SHA-256 与已通过测试的工作区一致。
2. **重复点击与幂等保护**：连续快速双击提交按钮，确认只创建一个有效任务、无重复模型调用。
3. **刷新恢复与状态一致**：任务执行中或完成后刷新页面，前端恢复展示的 DAG 状态、日志与产物下载入口与后端快照完全一致。
4. **单分支故障隔离**：触发无依赖分支失败，确认页面标红展示失败原因、主分支照常完成。
5. **受控异常与预算耗尽**：模拟模型超时 / 流式断开 / 工具失败 / 预算耗尽，确认页面给出明确错误原因、无静默重试、配额与工作区回收无残留。
6. **基础对话与附件冒烟**：流式输出、代码块/表格渲染正常；合法 PNG/PDF 上传解析通过，空文件/超限文件被安全拒绝并提示原因。

### 1.3 验收产出物
- 自动化报告（Markdown/JSON）：每条用例附 **截图、浏览器 console/pageerror 检查记录、关联后端任务 ID 与日志摘要**。

## 二、同条件交错对照实验（Runtime vs 直接调用循环）

### 2.1 实验设计（解决“并发 vs 串行”不对称）
在同一组多文件订单修复项目上，构建一个**具备完全相同工具集合、相同提示词、相同模型、相同并发度与相同调用预算的 Direct-Loop 基线**（不经过 AIOS 内核、调度器与 `TaskScope`）：

| 固定条件 | 记录指标 |
|---|---|
| 模型、任务集、提示词、工具集、并发度（如 2 路或 4 路对等并发）、Token 与调用预算完全一致 | 修复成功率、公开/隐藏测试通过率、端到端耗时、实际输入/输出 Token、进程峰值内存（`VmHWM`）、失败恢复表现 |
| **交错运行顺序**（如 `A-B-B-A-A-B`）减少云端时段抖动偏差 | 中位数（Median）、四分位距/波动范围（IQR/Min-Max）、失败轨迹分类 |

### 2.2 两阶段执行
1. **阶段 1（固定桩模型，10 轮交错）**：精确剥离并量化纯 Runtime 框架开销（调度、隔离、`ContextStore`、DAG 编排）。
2. **阶段 2（真实 DeepSeek 模型，3~5 轮交错）**：验证真实推理负载下的端到端耗时、Token、峰值内存与故障恢复差异。
