## 2. 分环节使用方式

1. 需求与架构：AI帮助拆分Syscall、Agent状态、上下文与OS隔离；队伍需对赛题逐项核对。
2. 编码：生成或修订代码草案；工具自动测试不能替代队员理解与审查。
3. 独立复核：对照冻结源码构造边界用例，保留失败日志，修复后复跑。
4. 实机实验：AI编排SSH、systemd委派与成本账本；测试由真实进程和系统执行，不是模型自报通过。
5. 交付材料：AI辅助排版、证据索引、对比说明与PPT，所有数值应能定位至原始日志。

## 3. 真实代表性交互（本会话摘录，已排除密钥和联系方式）

| 目的 | 用户实际提示词摘录 | 后续纠偏与验证 |
|---|---|---|
| 控制开发范围 | “里面混有不少ict比赛相关的无关代码注意别搞混了” | 独立目录与冻结包摘要，避免覆盖无关项目 |
| 检验框架而非模型 | “注意你要测试的是这个agent的框架好不好而不是这个api接入的模型怎么样” | 固定模型返回；同工具、同预算；区分冷启动与模型时间 |
| 排查上传 | “实测上传不了图片pdfword等文件” | 从真实文件选择控件上传四种格式，避免只测API |
| 保护凭据 | “你对我api密匙要保护好” | 独立持钥服务、Worker环境白名单、公开材料脱敏 |
| 建立新版本 | “你把交付包拷到你的工作区你进行下一步的完善” | 原包保留，新开发副本与源码SHA256绑定 |
| 防止虚假性能结论 | “继续按框架本身做同条件对照，固定模型和工具返回，重点优化调度、上下文共享、资源占用和故障恢复，保证质量不下降、减少失败。” | 保存两臂输入摘要、成功与失败记录，不把串并行差异当框架收益 |

以上是用户任务提示，不是对模型内部思维的记录。工程任务内部使用的系统提示词可查runtime/engineering_workflow.py的patch_messages，固定模型夹具位于tests/，不冒充真实模型结果。
