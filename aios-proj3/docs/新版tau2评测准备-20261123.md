## 已完成的新版准备

- 原生适配器 aios/benchmarks/tau_bridge.py，Agent 调用经 AIOSKernelRuntime 的 LLM Syscall，直接组与 Runtime 组使用同一个 provider.complete。
- 用户模拟器仍走直接提供商接口，并纳入同一预算回调。官方环境负责工具执行，Runtime 不替换官方工具或判分器。
- 官方消息转换器与 AssistantMessage/ToolCall 按需导入，保留工具调用关联 ID。
- SDK 新增 seed、tool_choice，Chat Completions 载荷保持参数。Responses 不支持 seed 时明确失败，禁止静默丢弃以声称同条件。
- 截断响应明确失败，工具调用 SSE 结果传递，框架失败不自动重放。
- 强制提供共享预算 reserve/settle 回调，无明文密钥文件或默认付费客户端。调用记录只包含数值与状态，不记录消息或凭据。
- 6 项免费协议测试通过，验证输入/输出/usage 一致、工具关联、预算阻断、故障无重放、载荷参数及截断失败。

这些是本地协议预验收，不是 tau2 官方任务得分。原生桥接类与官方 generate 的整体联调尚未完成。

## 正式付费评测前剩余步骤

1. 独立环境安装冻结 tau2 v1.0.1 依赖。该版本要求 Python >=3.12,<3.14，NUC 默认 Python 3.11 不能直接使用。不要替换系统 Python。当前 Windows Python 3.12.14 缺 litellm/loguru/deepdiff/docstring-parser 等。
2. 将原生桥接回调接入既有共享费用账本与可信持钥服务，预留未知计费失败，保留历史花费。历史账本累计已知加预留约 9.9032 元，总授权上限 20 元；这是历史估算，未核对供应商发票，不能视作实际账户余额。不得另清零成新的 20 元预算。
3. 每个官方 simulation 使用独立任务身份、Agent 预算和干净上下文。常驻 Kernel 的全局输出/调用上限也要与已授权批次对齐，不能在固定 tau-agent 上累计后意外触发默认 100 次限额。协议 preflight 中每个夹具使用独立 Kernel。
4. 少量官方任务做调试后单独归档，冻结新源码提交和官方 1155 项源/数据哈希。不得把旧 Runtime 提交冒充新内核。
5. 正式两组采用相同 Agent 模型、用户模拟模型、temperature、max_tokens、seed、官方工具及判分器，顺序交错。保存全部成功和失败、耗时、token、费用与资源峰值。绝不只挑最好轮或重试业务 0 分。
6. 新结果使用独立目录与日期，保留旧提交材料；按 custom 声明实际控制流程。正式提交前按 CONTRIBUTING.md 复核当前投稿规则、测试与格式要求。不把本地通过率称为官方排名。

本轮未运行付费模型请求。使用 GPT API 前会先告知用户。
