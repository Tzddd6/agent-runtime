## 防假修复门槛

1. 基线必须真实执行并失败，禁止将原本通过的项目当作修复。
2. 只允许修改3个明确的业务源文件，拒绝测试文件、路径穿越和额外文件。
3. 校验补丁JSON、源代码AST、导入与函数签名；不执行字符串中的任意协议外指令。
4. 评测方控制13项测试；必须13项实际执行、0跳过、0失败、0错误、进程退出码0。
5. 独立Worker受限执行；终止、回收和角色资源释放必须确认。
6. 最终ZIP回读源码摘要与已测试源码一致；下载接口再核对ZIP摘要。

这六条用于固定订单夹具，不构成通用恶意代码隔离的完整证明。五角色中分析/评审等包含确定性规则，不冒充独立模型智能体。

## 公平对照与性能

直接编排复用相同Worker与测试器，仅绕过Kernel/Syscall/DAG；比较的是框架控制层增量，并不是“带测试的Agent”对“无工具的裸聊天”。冷启动计入构造与回收，执行顺序Runtime→Direct、Direct→Runtime；温度0、每次输出上限4096、最多两轮。最终两对每轮提示词SHA一致。

| 指标 | Runtime | 直接编排 |
|---|---:|---:|
| 真实成功数 | 2/2 | 2/2 |
| 每个成功项目的真实测试 | 13/13 | 13/13 |
| 累计模型调用 | 2 | 2 |
| 累计输入/输出Token | 2864 / 474 | 2864 / 474 |
| 端到端中位数 | 5.677秒 | 3.034秒 |
| 扣除模型请求等待后的耗时中位数 | 0.681秒 | 0.550秒 |

Runtime端到端更慢。其一轮供应商耗时7.608秒，网络/供应商波动占主要差异，但扣除后仍有约0.131秒控制层增量；不能将差异全部归因于网络。初始化实测约0.009秒，当前证据也不支持把所有开销归因于冷启动。

免费固定响应3对均完成、提示词一致，Runtime中位数约0.595秒、直接约0.358秒，同样保留不利结果。固定响应不报告真实模型计费Token。

资源证据为协调进程CPU及Worker cgroup的CPU/内存峰值回执；未独立归因每组总RSS，不能宣称整个Runtime更省内存。
