# 新版原生 AIOS 正式评测报告

2026-11-23。使用 [sierra-research/tau2-bench](https://github.com/sierra-research/tau2-bench) v1.0.1 航空 base，全 50 题分别跑 Runtime 与直接调用各一次，共 100 次完整任务。

单轮结果为 **Runtime 74%，直接调用 68%**。质量观测值高 6 个百分点，但配对检验 p=0.5078，不能据此证明质量稳定提升。Runtime 总耗时和 Agent token 均略高，**尚未实现“更快、更省 token 且质量不下降”的总体目标**。

## 结果

| 指标 | 新版 Runtime | 直接调用 |
|---|---:|---:|
| 成功 / 全部题目 | 37 / 50 | 34 / 50 |
| 官方重算 Pass¹ | 74% | 68% |
| 总任务耗时 | 1160.78 秒 | 1125.87 秒 |
| 单题耗时中位数 | 21.34 秒 | 21.75 秒 |
| Agent 模型调用 | 432 | 433 |
| Agent 输入 token | 3,066,046 | 2,973,314 |
| Agent 输出 token | 60,123 | 60,899 |
| Agent token 总量 | 3,126,169 | 3,034,213 |
| 全部估算峰值费用，含模拟用户 | 1.1437 元 | 1.1579 元 |

Runtime 总任务耗时高 3.10%，Agent token 总量高 3.03%。尽管 token 略多，本轮缓存命中及用量结构使其估算费用略低，不能把这解释为框架必然节省费用。

同题配对中，Runtime 独自成功 6 题，直接调用独自成功 3 题。所有业务 0 分保留，没有挑最好的一轮或为提高分数重跑失败题。

## 已定位的主要框架开销

Runtime 的 432 次 Agent 调用累计排队 **21.913 秒**，平均 **50.72 毫秒 / 次**。

代码核对发现 FIFO 收集窗口设为 20 毫秒，但取下一条队列消息使用 50 毫秒阻塞超时。在空队列时，窗口截止时间无法约束该阻塞。固定输入、固定模型返回的本地免费回放也观察到约 60 毫秒额外单次开销，输入、结果与 token 记账完全一致。

因此，下一步应先修复空队列批处理等待，再进行新的冻结版本对照。不能把本轮真实模型输出路径差异全部归因于框架，也不能仅凭本轮 token 差异宣称上下文压缩收益。本轮评测过程中没有改动冻结内核。
