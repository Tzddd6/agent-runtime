## 6. 架构收口补齐与终版实机复测（2026-11-23 19:39）

对照最初《`proj3_系统总体框架.md`》，本轮将最后 4 项架构细节全部闭环并在 NUC（openEuler 24.03 SP4）上用真实 `deepseek-chat` API 完成实机复验：

1. **多路复用并发持钥进程（`aios/llm_core/model_service.py`）**：将单 Pipe + `self.lock` 串行架构重构为**请求 ID 多路复用 IPC + 持钥子进程内 `ThreadPoolExecutor(max_workers=16)`**，在保持纯内存密钥隔离（业务子进程零 API Key 继承）的前提下彻底破除多 Agent 真并发串行瓶颈：
   - 4 并发真实 `deepseek-chat` 总耗时从修复前的 **`4.916s`（0.81 calls/s）** 降至 **`0.542s`（7.38 calls/s）**，相对串行（`2.804s`）加速 **5.17×**，相对裸 4 并发 HTTPS（`1.050s`）更优。
2. **独立常驻 OS Worker 进程 + Linux `AF_UNIX` 心跳监督与崩溃自愈（`aios/os_kernel/worker_supervisor.py`）**：
   - Linux/openEuler 下采用原生 `AF_UNIX` Unix Domain Socket（Windows 下自动退化为 `stdio` 管道），独立常驻子进程支持周期心跳检测、`/proc/self/status` `VmRSS` 遥测与有界崩溃自动拉起（不静默重放失败写操作）。
3. **工程修复失败时动态派生第二轮修复 DAG 节点（`runtime/conversation.py`）**：
   - 第一轮独立测试校验失败时，通过 `WorkflowEngine` `spawn_tasks` 动态向有向无环图注入 `patch_round_2 -> verify_round_2` 并接入 `review` 节点（上限 1 轮防环路），由第二轮带失败反馈日志的补丁完成自愈。
4. **NUC 74/74 全量回归 + 真实 `tau2-bench` P2/P3/RSS 实机对照**（详细数据见 `reports/real_gaps_closed_nuc.json`）：
