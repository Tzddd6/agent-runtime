## 二、具体使用目的和研发环节分工

| 研发环节 | 人类参赛队员主导工作 | AI 工具辅助用途 | 验证与把关方式 |
|---|---|---|---|
| **1. 总体架构与赛题对齐** | 制定《`proj3_系统总体框架.md`》，确定 openEuler `cgroup v2`、纯内存持钥、`AF_UNIX` 常驻监督与 4 类 Syscall 边界 | 检索 2025–2026 前沿论文（AIOS / Cerebrum / LSFS / A-Mem / LiteCUA / AgentRace / AgentCgroup），对照设计梳理遗漏项 | 人工评审架构方案并逐条核对赛题 4.1–4.7 要求 |
| **2. 核心内核与 OS 原语实现** | 审定接口契约与安全红线（密钥不落盘、失败不静默重放、委派失败 fail-closed） | 编写/重构 `ModelService` 请求 ID 多路复用、`WorkerSupervisor` (`AF_UNIX`)、`TaskScope` 引用计数、`order_service` 防假修复护栏代码 | 本地 99 项单元测试 + openEuler 真机 `validate_linux.py` 实测 |
| **3. 独立边界对抗与缺陷关闭** | 组织“双 Agent 交叉对抗”机制，要求独立复核端在不改动主仓的前提下构造破坏性边界测试 | 独立复核 Agent（Codex）先后产出 3 轮边界复核（12 项 P1–P5 边界缺陷 + 5 项 `OA-01`~`OA-05` 交付缺陷）；主开发 Agent 逐项修复并纳入正式 `tests/` | 所有复核用例合并进正式测试集并全部实跑通过 |
| **4. 实机评测与对照归因** | 规定“必须区分模型能力与 Runtime 能力，补齐 Bare 直接调用对照组，禁止拿模拟桩冒充真实云端” | 编写 NUC 自动化评测脚本、Bare 对照脚本、Playwright 浏览器验收脚本与 Matplotlib 图表生成脚本 | 所有性能与通过率数字均来自 NUC 原始 JSON 与导出日志 |
| **5. 文档、PPT 与交付封板** | 审定技术报告口径、收敛夸大表述、确认 MIT 许可证与能力边界 | 辅助排版技术报告（`.md`/`.docx`/`.pdf`）、14 页答辩 PPT、`FINAL_CHECK.sh` 与 `FILES.sha256` | 逐项核对 `FILES.sha256` 与 NUC 虚拟环境版本绑定实跑 |

## 三、主要提示词与多轮迭代交互方式（代表性交互摘要）

> 说明：以下为本项目实际研发过程中具有代表性的交互提示与多轮纠偏模式摘要（用于还原团队如何驱动和约束 AI 工具，而非宣称逐字原始聊天记录）。

1. **架构缺口对齐与闭环驱动**
   - **交互意图**：要求主开发 Agent 对照最初总体框架逐项排查未闭环的 OS 机制（常驻 Worker + Unix Socket 心跳、持钥进程单 Pipe 锁并发瓶颈、动态二轮修复 DAG、真实公榜 P2/P3/RSS 实测），给出改动方案并在真机实测。
2. **双 Agent 独立对抗复核与纠偏**
   - **交互意图**：将主仓快照交给独立复核 Agent（Codex），明确约束“只读检查、独立构造边界用例、不信任原报告断言”，先后暴露出作用域误删、SQLite 删除原子性、IPC 凭据撤销、未配置模型隐式降级参考答案（`OA-01`）、`cgroup` 控制台属性错名（`OA-02`）、下载 ZIP 未二次验签（`OA-03`）等真实缺陷，再回传主开发 Agent 逐一闭环。
3. **模型能力 vs Runtime 能力严格解耦**
   - **交互意图**：明确要求“区分模型能力好还是 Runtime 好，对所有存在失败用例的公开任务子集补跑同题 Bare 直接 HTTPS 对照组”，借此精准定位到 `adapter.py` 对 `finish_reason="length"` 的 fail-closed 502 守卫交互与 `HumanEval/32` 随机测试波动，避免了错误归因。
4. **文档口径收敛与可复现验收约束**
   - **交互意图**：多轮审查交付包，要求删除“全面领先”“绝对安全”“100% 模型原因”等越界表述，显式保留“LiteCUA 为内存态模拟、公开子集非官方榜单、未证明所有场景均快于直接调用”三条边界，并在 NUC 虚拟环境中按手册实跑版本绑定的 `FINAL_CHECK.sh`。
