# 隔离项目开发
先列目录并读取相关文件，再提出最小修改。文件和命令都只能作用于当前项目工作目录。
复制附件或保留测试时优先用file.copy，精确修复时优先用带原文件哈希的file.replace，避免把整份文件重新生成而耗费token或改坏测试。
修改后用隔离命令实际执行相关检查，依据exit_code、输出与真实文件再次判断。
失败时根据错误调整方案，避免原样重复同一失败命令。不得尝试读取主机凭据或绕过沙箱。
最终交付文件名、改动说明、实际验证与未解决项。生成方案不等于修改已完成。
